# Auditor Gate V2 Rebaseline Design

## Objective

Rebaseline Month-1 PAPER Auditor controls around least privilege and authorized runtime integrity without claiming kernel or network containment. Custom WFP/ALE work is deferred as disproportionate to the paper experiment. The 30-day experiment and every IBKR order operation remain unauthorized.

This design applies only while all three values are true:

- `PAPER_ONLY=true`
- `LIVE_ALLOWED=false`
- `REAL_MONEY_ALLOWED=false`

It expires before any live or real-money authorization.

## Threat Model

Gate V2 proves that the approved, hash-bound Auditor runtime executes in a separate non-elevated Windows identity with only the filesystem capabilities needed to consume immutable exports and create reports. It proves that no broker control path is granted to that approved runtime.

Gate V2 does not prove containment of a compromised Auditor identity. The restricted identity can reach the authenticated local IB Gateway socket. An independently implemented API client could potentially negotiate an API session without receiving separate broker credentials from this repository. Therefore:

- `AUDITOR_ORDER_AUTHORITY_GRANTED=false` means no authority is granted by the experiment architecture.
- `AUDITOR_BROKER_CONTROL_PATH_AUTHORIZED=false` means the approved runtime has no supported broker-control interface.
- `AUDITOR_TECHNICAL_SOCKET_REACHABILITY=true` records the observed localhost connection.
- `AUDITOR_UNAUTHORIZED_RAW_API_PATH_POSSIBLE=true` records the residual technical possibility.
- `AUDITOR_COMPROMISE_CONTAINMENT_NOT_CLAIMED=true` prevents Gate V2 from being represented as a sandbox.

The legacy firewall rule remains installed and unmodified but contributes no positive evidence:

`LEGACY_FIREWALL_CONTROL=INEFFECTIVE_FOR_LOOPBACK_REQUIREMENT`

## Gate Name And Version

The canonical gate is:

`AUDITOR_LEAST_PRIVILEGE_AND_RUNTIME_INTEGRITY_GATE_V2`

Compatibility output may also expose:

`AUDITOR_ISOLATION_GATE_V2`

Both fields must have the same value. The unversioned `AUDITOR_ISOLATION_GATE` must not silently reinterpret V1 evidence as V2 evidence; when retained for compatibility it must be derived from the V2 evaluator and identify `gate_version=V2` in its source receipt.

## Required Evidence Receipt

V2 requires one new consolidated receipt generated by the corrected probe from commit `d73a598d` or a descendant with the same security behavior. The receipt must be produced during one execution under the real `CodexAuditorV1` token and must bind:

- exact effective SID `S-1-5-21-214160970-1890373857-4055601883-1012`;
- `token_elevated=false`;
- corrected probe and runtime-manifest SHA-256 values;
- probe-target manifest SHA-256;
- all ten target-validation rows;
- all ten capability outcomes;
- functional immutable-bundle verification outcome;
- report path and creation outcome;
- observed endpoint classifications, retained only as residual-risk evidence.

Old partial receipts remain preserved but cannot independently produce V2 PASS. In particular, the prior `UNSAFE_TARGET_PATH` receipt does not prove secret, broker-path, database, or export denials because it aborted before capability execution.

Provisioning must not be rerun unless required to deploy the corrected hash-bound runtime. If deployment is necessary, it receives a separate reviewed administrator checkpoint limited to runtime files and manifests; account, ACL, and firewall changes are out of scope.

## Gate Predicate

V2 is `PASS` only when a single accepted receipt proves all of these predicates:

| Predicate | Required value |
|---|---|
| Separate process | `true` |
| Separate Windows identity | `true` |
| Effective SID | exact expected SID |
| Token elevated | `false` |
| Secrets read | `DENIED` |
| IBKR settings/secret read | `DENIED` |
| SMTP secret read | `DENIED` |
| Live database mutation | `DENIED` |
| Execution-lock access | `DENIED` |
| Trader-context access | `DENIED` |
| Audit-input mutation | `DENIED` |
| Immutable-export read | `ALLOWED` |
| Auditor-report write | `ALLOWED` |
| Approved runtime imports broker/order module | `false` |
| Order authority granted | `false` |
| Broker credentials supplied | `false` |
| Execution adapter supplied | `false` |
| Trader runtime IPC supplied | `false` |
| Runtime manifest verification | `PASS` |
| Functional Auditor | `PASS` |

Missing, stale, contradictory, partial, cross-run, or configuration-only evidence yields `BLOCK`. Network denial is deliberately absent from the PASS predicate.

## Structural Authority Checks

The approved Auditor runtime must remain a minimal standalone runtime under `C:\ProgramData\CodexAuditorV1\runtime`. Source and tests must prove that it does not import or bundle:

- `ibapi` or another IBKR protocol client;
- `ibkr_paper_30d.broker`;
- `ibkr_paper_30d.trader_invocation`;
- execution-lock acquisition code;
- process-control or IPC hooks into the Trader;
- order submit, cancel, or modify symbols.

These checks establish the authorized runtime surface, not the impossibility of arbitrary replacement code under a compromised identity.

## Residual Risk Acceptance

`AUDITOR_MONTH1_PAPER_RESIDUAL_RISK_ACCEPTANCE_V1.json` must be canonical JSON and include:

- scope and schema version;
- expected Auditor SID;
- `paper_only=true`, `live_allowed=false`, `real_money_allowed=false`;
- observed IPv4 and IPv6 loopback reachability to port 4002;
- explicit possible unauthorized raw API path;
- explicit statement that compromise containment is not claimed;
- approved-runtime structural denials;
- source evidence hashes;
- expiration triggers;
- Owner decision provenance.

Expiration occurs at the earliest of:

- any request to enable live or real-money execution;
- any change from the bound paper-account identity;
- any material Auditor runtime or privilege-boundary change;
- completion or termination of the Month-1 experiment.

The artifact must not state that the Auditor lacks an authenticated-session path merely because no credential is supplied. It must state that the already authenticated Gateway may accept another local API client.

## Paper-Only Proof

`PAPER_ONLY=true` is accepted only when the existing broker-derived paper identity gate passes against the protected expected-account hash. A configuration flag alone is insufficient. Gate V2 does not alter that independent prerequisite.

## Reports And Gate Matrix

Create `AUDITOR_ISOLATION_GATE_V2_REPORT.md` with:

- exact accepted evidence paths and SHA-256 values;
- every Gate V2 predicate and observed value;
- legacy firewall classification;
- loopback residual-risk statement;
- WFP deferral decision;
- explicit unresolved predicates;
- final V2 gate result.

Create or update `CODEX_IBKR_PAPER_30D_PREFLIGHT_V4.md` to replace the obsolete V3 Auditor narrative. It must keep `AUTONOMOUS_TRADING_STATUS=BLOCKED`, identify Market Data as the next independent blocker only after Gate V2 passes, and never authorize a lifecycle order.

Update `state/ibkr_paper_30d/reports/updated_gate_matrix.json` atomically. The matrix must include the V2 gate name and version, the five residual-risk declarations, WFP deferral, paper/live restrictions, market-data status, and `READY_FOR_HARMLESS_PAPER_LIFECYCLE_TEST=false`.

The implementation-status builder must consume a validated V2 receipt rather than trust a bare `gate=PASS` value. Invalid or legacy receipts remain blocked.

## Market Data Handoff

After Gate V2 is proven, the only prioritized blocker is `MARKET_DATA_POLICY_FROZEN`. During an eligible US regular trading session, use the existing read-only SPY/QQQ/IEF collector and the preregistered observation count, duration, timestamp, entitlement, bid/ask, and health requirements. Thresholds may not be loosened to force PASS.

Even when Gate V2 and Market Data pass, this scope only returns to the Owner. It does not authorize submission, cancellation, modification, directional trading, or the start of the 30-day experiment.

## Testing

Tests must first fail for V1-only, partial, stale, mixed-run, wrong-SID, elevated-token, missing-capability, and broadened-runtime evidence. Positive tests require the complete V2 predicate. Regression coverage must preserve:

- truthful `DENIED`, `NO_LISTENER`, `CONNECTED`, and `OTHER` endpoint classification;
- all ten target-validation rows;
- outside-root and reparse rejection;
- immutable export and runtime hash validation;
- V1 evidence preservation without V2 promotion;
- paper-identity proof independent from local configuration;
- permanent `LIVE_ALLOWED=false`, `REAL_MONEY_ALLOWED=false`, and order authorization false.

Run the complete `tests/ibkr_paper_30d` suite, Auditor runtime/provisioning tests, fault injection, PowerShell AST parsing, security scan, secret scan, forbidden-path scan, and `git diff --check`.

## Administrator Checkpoint

No WFP, firewall, ACL, account, C++ toolchain, SDK, or driver action is permitted.

If the corrected runtime is not installed under the protected ProgramData manifest, stop and prepare a separately reviewed runtime-only deployment checkpoint. It must publish a new script/runtime SHA-256 and exact install/rollback commands but must not execute them. If the corrected runtime is already installed and hash-bound, no administrator action is required.

## Final Safety State

Until the real corrected receipt proves every V2 predicate:

- `AUDITOR_ISOLATION_GATE_V2=BLOCK`
- `MARKET_DATA_GATE=BLOCK` unless independently frozen from valid observations
- `READY_FOR_HARMLESS_PAPER_LIFECYCLE_TEST=false`
- `REAL_BROKER_WRITE_CALLS=0`
- `AUTONOMOUS_TRADING_STATUS=BLOCKED`
